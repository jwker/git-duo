圆形玻璃悬浮按钮 + 单页分组弹层

按钮是 56pt 的玻璃圆片，浮在右下角（Tab 栏之上）；点开是一张原生 Form 弹层， 从「选目标仓库与目录」一路走到「上传成功 + 复制相对路径」。这是三个方案里最贴 iOS 官方语言的： 按钮形状与材质用系统那一套，内容组织用原生 Form，没有一处自绘控件。

按钮规格

项取值理由
形状 / 尺寸圆形 56 × 56 pt，圆角 2856 是 iOS 主按钮的最小舒适尺寸；圆形让「浮」的感觉成立
位置右边缘内缩 18pt，底边在 Tab 栏顶上方 16pt（= 设备安全区 34 + 82 视觉高度）拇指可达区；同时不压 Tab 栏
材质.glassEffect（regular），叠 Theme.Palette.glassTint铁律 #4：玻璃只属导航层，FAB 属悬浮层，不进内容层
图标SF Symbol photo.badge.plus（落地前用 NSImage(systemSymbolName:) 探针核实）「加一张图」的语义；备选 square.and.arrow.up
命中区视觉 56pt，外扩到 64pt 透明命中区视觉尺寸不等于命中尺寸
出现时机全局：每个页面常驻（首页 / 探索 / 仓库列表 / 搜索 / 仓库页 / 详情页 / 设置页）入口是全局能力，不绑某一页；键盘弹出时收起，文本输入中隐藏
目标记忆第一次选过目标后，之后点开直接进入上传，不再问仓库记忆项 = 仓库 + 目录 + 分支；失效时回落到选目标
滚动行为随内容滚动吸底，滚到底不隐藏隐藏式 FAB 会让用户以为功能没了

弹层结构：第一次与之后不一样

目标（仓库）只问一次。第一次点开是「选目标」；之后每次点开都直接进上传， 目标以一行只读摘要带在顶部，旁边一个「换目标」把它带回选目标那一屏。

分组内容备注
目标（首次）仓库 › 目录 › 分支（三行，各带 chevron）未选仓库时目录行显示「先选一个仓库」
目标（之后）一行只读摘要 + 「换目标」记忆失效（仓库改名 / 目录被删 / 分支不存在）时自动回落到选目标
图片相册选择器 + 压缩预览（原价 → 压缩后）压缩规则复用 UploadIntake（≤1MB 且格式可渲染则原样放行）
提交提交说明输入框 + 「上传」主按钮写入走 PUT /contents，必须有 commit message
成功✓ 图标 + 相对路径 + 「复制路径」按钮路径 = 仓库内相对路径（不含仓库名）
为什么成功提示不只用 Toast：现有 Toast 是纯文字块，承载不了「复制」这个动作。 所以成功态留在弹层里（弹层不自动关），复制按钮就在路径旁边； 如果用户中途把弹层划走，再用一句 Toast 兜底告知「已上传」。

落地归属（照架构铁律）

  • 按钮组件 → Packages/GitDuoDesign/Components/FloatingActionButton.swift （.glassEffect 只能出现在设计包，AGENTS.md §3 铁律 #4）
  • 按钮的安放点 → GitDuo/App/MainTabView.swift 的 .overlay(alignment: .bottomTrailing)， 与 Toast 同一个通道（那边已有一层 overlay，四个 Tab 与七条导航栈共用）。 不是每页各放一个 —— 全局入口只能有一个实例。
  • 弹层 → GitDuo/Features/Repo/Views/Sheets/UploadImageSheet.swift， 沿用 AddFileSheet 的「原生 Form + 组合根注入 UploadIntake」写法
  • 选仓库 / 选目录的判据 → 领域层 GitDuoKit（LoadRepositoriesPage / LoadRepoTree 复用）， 铁律 #14：规则写纯函数，不写 ViewModel

取舍

  • 优点：形状最像 iOS 自己的东西；圆形不占横向空间，代码页与列表页都不挤； 56pt 命中区在单手下够得着。
  • 代价：圆形按钮只有图标，可发现性弱——用户第一眼不知道它是"上传图片"。 缓解办法：首次进入时在按钮左侧弹一次玻璃提示气泡（见右侧「?」可试）， 或把图标换成带「+」的 photo.badge.plus 让意图更直白。
  • 代价：一次要选仓库 + 目录 + 分支 + 图片 + 提交信息，弹层偏长； 选仓库那一段需要 push 一级（见 sheet-flows.html 的流程对比）。
  • 注意：按钮全局常驻，所以「目标记忆」是必需品而不是加分项 —— 没有它，全局入口每次都要重选仓库，用两次就烦了。
