「上传图片到仓库」—— 悬浮按钮与弹层

功能链：全局悬浮按钮 → 弹层 → 先定目标仓库的一个目录 → 选图 → 自动压缩 → 上传 → 提示成功 → 附带相对路径与复制按钮。 目标（仓库）只问一次：第一次选过仓库与目录之后，之后每次点开都直接进上传。 下面是三个按钮形态方案、一份弹层内部流程对比，以及一份需要你拍板的问题清单。 所有配色都取自本仓 Theme 令牌（浅色 #F6F8FA 页底 / #FFFFFF 卡面 / #C2410C 强调 / #EA580C 主按钮）， 每个页面右上角都能切深色档。

2026-10-23 选型：方案 A（圆形玻璃按钮）+ S3（两段折中）。 实施以 final-a-s3.html 为准 —— 里面含完整的规格表、文案、失效兜底与落地清单。 本页与 B / C 两页保留作提案存档。
已定的两条口径（2026-10-23）： ① 悬浮按钮是全局的 —— 每个页面常驻，不是只在仓库页； ② 目标只需选一次 —— 没选过才选，选过就直接上传。 两条合起来意味着「上次目标记忆」是必需件，不是加分项。

弹层内部流程

三个方案共用同一条功能链，差别只在弹层里怎么组织 —— 见 《弹窗内部流程对比》： S1 单页 Form · S2 逐级推进 · S3 两段折中。

功能链（三方案一致）

① 悬浮按钮（全局）→ ② 目标：没选过才选→ ③ 选图→ ④ 自动压缩→ ⑤ 提交（commit）→ ⑥ 成功 + 复制相对路径

第二次起，第 ② 步消失（目标已记住），直接从选图开始。

可以直接复用的既有件（不重造）

环节复用谁说明
压缩 / 转码GitDuoKit.UploadIntake + GitDuoCore.ImageProcessor ≤1 MB 且格式网页端能显示就原样放行；否则自适应压缩（2048@0.9 → 640@0.5）；HEIC/TIFF 一律转码并改扩展名
写文件GitHubRepoContentEndpoint.putFile base64 ⇒ 单文件 ≤1 MB 是硬限，这就是压缩目标取 1 MB 的原因
选目录LoadRepoTree（contents API）逐层取；目录不存在时写入会一起创建
提交信息CommitSheet / CommitDraft现有「添加文件 → 提交」那一套已经跑通，新入口应汇入它
成功提示GitDuoDesign.Toast纯文字块，承载不了「复制」动作 ⇒ 成功态留在弹层里，Toast 只做兜底
复制路径RepoCopy.clipboardPath 的口径 + UIPasteboard相对仓库根的路径

必须守住的硬约束

  • 必须先有目标才能上传：没有仓库与目录就没有上传动作 —— 按钮在未选目标时是「下一步」而非「上传」。
  • ≤1 MB：压不下来就明确拦下并给替代动作（去网页端），不静默截断。
  • 目录不能单独新建：GitHub 的 PUT /contents 不建空目录， 新目录随文件一起产生。文案要写「目录（新）」。
  • 只有有 push 权限的仓库能写：选仓库时只列自己的仓库（permissions.push）， 他人仓库不给上传入口（铁律 #7：可写性只有一个来源）。
  • 玻璃只在设计包：按钮组件放 GitDuoDesign/Components/， .glassEffect 不许出现在 App 层（铁律 #4）。

维度A 圆形B 胶囊C 贴边菜单

倾向性意见（供你参考，不替你拍板）： 若优先「与仓库既定的自绘件退休方向一致」⇒ 选 A，并把「只有图标」的问题用 首次出现的提示气泡补上；若优先「用户一看就知道能干什么」⇒ 选 B； 若这是高频重复动作（你每天往同一个仓库传图）⇒ 选 C，代价是多一个记忆存储与失效兜底。

需要你裁定的点

  1. ~~选 A / B / C 哪个按钮形态。~~ 已定：A（圆形玻璃按钮）。
  2. ~~弹层内部走 S1 / S2 / S3。~~ 已定：S3（两段折中）。
  3. 上下文优先要不要做（防误传）。站在某仓库页面时，默认目标 = 当前仓库 + 当前目录， 而不是记忆里的那个 —— 这是新口径，等你点头。
  4. 记忆的粒度。我按「仓库 + 目录 + 分支」三件记（沿用 BranchMemoryStore 的套路）。 若只记仓库、目录每次都重选，首次之后仍要两次点击。
  5. 记忆失效的兜底。仓库改名 / 目录被删 / 分支不存在时，自动回落到选目标，并提示一句 「上次的目标已失效」—— 还是静默回落？
  6. 全局按钮与键盘 / 输入框的冲突。我按「键盘弹出时收起、文本输入中隐藏」处理。
  7. 分支要不要让用户选。默认取该仓库的默认分支（与现有 LoadRepoTree 的回落一致）， 但弹层里给一行可改。
  8. 相对路径的口径。我按「相对仓库根」写（assets/photos/photo-20261017-143012.jpg）， 与 README 里贴图的写法一致。要「相对当前目录」也行，说一声。
  9. 文件名规则。相册没有文件名 ⇒ 沿用 UploadFileName.photo 的自拟名 （形如 photo-20261017-143012.jpg）。要不要改成「保留原文件名，只换扩展名」？
  10. 是否允许「新建目录」。默认允许（路径填一个不存在的目录，随文件创建）。
  11. 成功态的位置。默认：弹层不关，整屏换成成功态（含复制按钮）； 划走弹层时再用 Toast 兜底一句「已上传」。
