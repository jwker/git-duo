弹层里怎么走：三种流程

三个悬浮按钮方案共用同一条功能链（选仓库 → 选目录 → 选图片 → 压缩 → 提交 → 复制路径）。 差别在于这条链在弹层内部怎么组织。下面三张是同一个任务的两种走法与一种折中。

S1 · 单页 Form

一张 Form 装下全部内容：目标分组、图片分组、提交分组。用户在一屏里看到全部字段， 选仓库/目录靠 push 一级原生列表。

S2 · 逐级推进（NavigationStack）

弹层里放一条 NavigationStack：选仓库 → 选目录 → 选图片 → 提交。 每一步一屏，右上角「下一步」推进。最贴 iOS 习惯，也最容易加搜索与取消。

第一段是「选目标」：搜索框 + 仓库结果，选中仓库后就地展开目录面包屑（不再 push）； 第二段是「选图 + 提交」合并在一屏。省一级，但目录选择在小屏上略挤。

改动面最小：一个 sheet + 两个 push 列表中：sheet 内多一层栈 + 每层一个列表中：目录展开态要自绘一点
风险屏太长、字段多时挤层级深，用户容易「推过头」小屏上目录面包屑换行
推荐度中高高（若要做「最近仓库」快捷项）
我的推荐：S2。选仓库与选目录这两步，仓库里已经有现成的列表层 （仓库列表与目录浏览），S2 直接把它们接进 NavigationStack，不多造控件； S1/S3 都要为「在 Form 里选目录」另做一套自绘展开（与本仓「少自绘」的方向不合）。 若你还想保留「一键传到上次的目标」，就取 S3 的第一段做成 S2 里的第一屏（一个芯片 + 一个列表）。

首次与之后：流程不一样

目标（仓库）只问一次 ⇒ 三种流程都有两个入口：

流程第一次（无记忆）之后（有记忆）
S1 单页 Form选目标 → 选图 → 提交顶部一行只读目标 + 选图 → 提交
S2 逐级推进选仓库 → 选目录 → 选图 → 提交直接从「选图」开始，目标以摘要行置顶
S3 两段折中目标段（搜索 + 目录面包屑）→ 图片 + 提交目标段只剩一行摘要，其余同左
记忆失效怎么办：仓库改名 / 目录被删 / 分支不存在时， 不能把用户带到一个写不上去的目标上 —— 直接回落到「选目标」那一屏，并提示一句「上次的目标已失效」。 这条是全局入口的必备配套：按钮在每个页面都有，记忆错了会影响每一次上传。

三种流程都要遵守的两条硬约束

  • 目录必须能新建。GitHub 的 PUT /contents 不能创建空目录 —— 新目录只能随文件一起产生。所以「新建目录」不是「先建目录再传文件」， 而是「填一个还不存在的路径 + 传文件」。界面文案要写成「目录（新）」，别让人以为要先建。
  • 单文件 ≤1 MB 是硬限（contents 走 base64）。 这正是压缩目标取 1 MB 的原因；压不下来时必须明确拦下并给出替代动作，而不是静默截断。
