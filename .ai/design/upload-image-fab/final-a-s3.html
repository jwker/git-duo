已选定方案 AS3 两段折中

最终稿：圆形玻璃悬浮按钮 + S3 弹层

按钮 = 56pt 圆形玻璃钮，全局常驻；弹层 = 一张原生 Form， 顶部一行目标摘要（仓库 · 目录 · 分支，记忆作默认），下面依次是图片与提交。 换目标不 push、不嵌套弹层，在原位就地展开。

流程

点悬浮钮→ 目标（默认已选，点那行可换）→ 选图 · 自动压缩→ 提交→ 成功 + 复制路径

第一次用时目标一行显示「尚未选择目标」，主按钮置灰；选过一次之后，这一行就是默认目标， 直接选图即可上传。

目标摘要行（S3 的关键那一行）

元素内容说明
仓库jwker/my-app加粗、正文色
路径assets/photos · main等宽字体、次级色；目录相对仓库根，分支跟在后面
点击整行去选仓库（push 一层）首屏不出现任何列表；仓库列表用现成的那一层
摘要行里写的jwker/my-app + assets/photos · main仓库全名 + 相对仓库根的目录 + 分支；三样写全，不缩写
为什么不在 S3 首屏就地展开选择器。就地展开会把一层列表铺在上传表单上方， 弹层一下变成三层（目标摘要 / 列表 / 图片与提交），层级与滚动都乱了。 改成「点已选的那一行 → push 选仓库 → 选完 pop 回来」： 首屏永远是「目标一行 + 图片 + 提交」，用户想改时点那一行，进去选，改完回到原地。 仓库列表与目录浏览都复用现成的那一层，不多造控件。

记忆的写入与失效

场景行为
用户在弹层里改了目标立刻写回记忆（仓库 + 目录 + 分支三件）⇒ 下次打开就是新目标
用户正站在某个仓库 / 目录里上下文优先：默认目标 = 当前仓库 + 当前目录（不拿记忆）
记忆里的仓库改名 / 仓库没了静默回落到选目标（不弹提示、不报错）
记忆里的目录被删静默回落到仓库根
记忆里的分支不存在静默回落到该仓库的默认分支（分支默认取默认分支、可改）
没选过摘要行显示「尚未选择目标」；主按钮置灰
失效一律静默回落。记忆项失效时直接换成能用的值（仓库 / 默认分支 / 仓库根）， 不提示、不报错 —— 用户看到的是一个仍然可用的目标，而不是一条看不懂的警告。
全局按钮 + 记忆默认 = 误传风险（已处理）。 按钮在每个页面都有，用户站在 A 仓库的代码页点开，记忆里的目标是 B 仓库 ⇒ 很容易把图传到 B 去。 两道防线：
① 上下文优先：当用户正站在某个仓库 / 目录里，默认目标 = 当前仓库 + 当前目录；没有上下文才用记忆； ② 摘要行显式：仓库名 + 目录 + 分支三样全写出来，且上传成功后 Toast 补一句「已上传到 jwker/my-app / assets/photos」。
两条一起做。

安放点MainTabView 的 .overlay(alignment: .bottomTrailing)，与 Toast 同层

压缩与写入

  • 压缩复用 UploadIntake + ImageProcessor：≤1 MB 且格式网页端能显示 ⇒ 原样放行； 否则自适应压缩（2048@0.9 → 640@0.5），HEIC/TIFF 一律转码并改扩展名。
  • 写入走 PUT /repos/{owner}/{repo}/contents/{path}（base64 ⇒ 单文件 ≤1 MB 硬限）。
  • 提交说明复用 CommitSheet / CommitDraft 那一套。
  • 目录不存在 ⇒ 随文件一起产生（GitHub 不能建空目录），文案写「目录（新）」。
  • 只列有 push 权限的仓库（铁律 #7）。

成功态

上传成功后弹层不关，整屏换成成功态：✓ + 仓库与分支 + 带仓库名的相对路径 + 「复制路径」按钮 + 「继续上传」/「完成」两个次要动作。 用户把弹层划走时，再用一句 Toast 兜底「已上传到 jwker/my-app / assets/photos」。

项取值
相对路径口径相对仓库根、带仓库名 ⇒ jwker/my-app/assets/photos/photo-20261017-143012.jpg
文件名沿用 UploadFileName.photo（photo-yyyyMMdd-HHmmss.ext），转码时扩展名跟着换
新建目录允许；不存在的目录随文件一起建出来（GitHub 不能建空目录）
注意：这一条与现有的 RepoCopy.clipboardPath 不是一回事。 那边复制的是仓库内路径（只有根目录才给仓库全名），本功能要的是带仓库名的 ⇒ 需要一个新函数，不要顺手改旧的（改了会让代码浏览页复制出来的路径多出一截）。
