贴边悬浮坞 · 玻璃菜单 · 一步直达

按钮贴在屏幕右边缘（只露出一半），点开是一张玻璃小菜单。菜单第一项是快捷路径： 直接上传到上次用的仓库与目录，一步到位；想换目标再走完整流程。适合「我天天往同一个仓库传图」的人。

按钮规格

项取值理由
形状56 pt 圆，只露出右半（right: -13pt）贴边元素不占内容宽度，也不会被误认为列表的一部分
位置屏幕垂直中偏上（不是底部）贴边按钮若同时贴底，会与 Tab 栏挤在一处
图标square.and.arrow.up（通用上传）菜单里有多种上传，用通用符号更合适
菜单玻璃卡片 268 pt 宽，贴右缘展开iOS 26 的玻璃浮层语言；点外面收起
菜单项① 上传到 my-app / assets/photos（快捷）② 换个仓库… ③ 上传任意文件…第 ① 项就是「记住的目标」——目标只问一次，这条路是常路
出现时机全局：每个页面常驻键盘弹出时收起、文本输入中隐藏
目标记忆第一次选过目标后，之后点开直接进上传记忆项 = 仓库 + 目录 + 分支；失效时菜单第一项自动退成「换个仓库…」

弹层结构

目标只问一次，所以「走快捷路径」是常态而不是特例： 点悬浮钮 → 选图 → 确认提交，目标已经在那儿了。只有第一次（或记忆失效）才需要问仓库。

段快捷路径（常态）完整路径（首次 / 记忆失效）
目标只读一行「my-app / assets/photos · main」，可点开改仓库 › 目录 › 分支
图片相册选择 + 压缩预览同左
提交提交说明 + 上传同左
成功✓ + 相对路径 + 复制路径同左
这条方案的「上传目标记忆」是必需件。要记住的不只是仓库，还有目录与分支。 记忆项要有失效与兜底：仓库改名 / 目录被删 / 分支不存在时，菜单第一项要自动退回「换个仓库…」， 而不是把用户带到一个写不上去的目标上。

取舍

  • 优点：常客路径最短（一次点 + 一次选图 + 一次确认）；按钮不遮内容； 菜单是 iOS 26 玻璃浮层的正统形态。
  • 代价：贴边按钮比圆钮更「隐形」，可发现性最弱； 玻璃菜单是自绘浮层（系统没有等价物），与「少自绘」的方向有张力。
  • 代价：多了一个记忆存储要维护，且要有失效兜底。
