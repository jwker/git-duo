# `.ai/` 初始化说明书（init.md）

> **这份文件的用法** —— **新项目开工的第一件事**就是把它交给 AI，说一句
> 「按 `.ai/init.md` 把 `.ai/` 建起来」。AI 照 §2–§5 一次建好目录骨架与模板文件，
> 并把 §4 那一整节**原样**写进 `AGENTS.md`。
>
> ⚠️ **建完之后 AI 只看 `AGENTS.md`** —— 存放规则以项目里的 `AGENTS.md` 为准，
> 执行任务**不需要再读本文**。本文留在 `.ai/init.md` 只剩一个用途：**下次开新项目时拿来复用**。
>
> ⚠️ 本文**不含任何项目专有内容，可直接复制到下一个项目，不用改**。

---

## 1. 一句话口径

`.ai/` 下**全部进库** —— 不给它加任何 ignore 规则，放进去就会被提交。

所以判据只有一条 —— **换台电脑、换个人，需不需要知道它**：

| | 该放进来 | 不该放进来 |
|---|---|---|
| 判据 | 契约与知识沉淀 · 谁接手都要知道 | 临时产物 · 因人而异 · 删了能重建 |
| 例 | 规则 · 任务书 · 长期记忆 · 工具源码 · 证据件 | 密钥 · 一次性中间产物 · 会话日志 |

⚠️ 既然全进库 ⇒ **`.ai/` 下绝不许放密钥**（`.env` / API Key / token）：放进去就等于提上去。

---

## 2. 要建出来的结构

```
.ai/
├── init.md      本文（脚手架；建完后 AI 不读它）
├── memory.md    长期记忆
├── prompts/     任务书 / 分阶段计划
├── tools/       工具与脚本源码
└── evidence/    被引用的证据件（渲染页 / 截图）
```

| 路径 | 放什么 |
|---|---|
| `init.md` | 本文 —— 脚手架。**建完后 AI 执行任务不读它**，规则以 `AGENTS.md` 为准 |
| `memory.md` | 长期记忆：实测硬事实 / 已定口径 / 方法论（**不放任务与进度**） |
| `prompts/` | 任务书 / 分阶段计划 / 待办清单 —— **进度只在这里** |
| `tools/` | 工具与探针的源码（可运行的东西） |
| `evidence/` | 被代码注释或结论引用的证据件 |
| `rules/` | **按需创建**（别预建空目录）：规则专题，只放长到必须分篇的 |

> **为什么规则正文不直接写进 `.ai/rules/`**：AI 的常驻入口约定在仓库根 `AGENTS.md`，
> 藏在 `.ai/` 里没人会去读。`rules/` 只在真有一篇长专题时才建，建时一并写 §3 那个 README。

> ⚠️ **不为临时产物建目录**：`.ai/` 下只有上表这几项（`rules/` 还是按需），没有"日志 / 缓存 / 会话"这类目录。
> 需要落盘的临时东西放仓库外或构建目录，别往 `.ai/` 里丢。

---

## 3. 要生成的模板文件

### `.ai/memory.md`

```markdown
# 长期记忆

> 只留"换个人接手也要知道"的东西：**实测硬事实、已定口径、方法论**。
> 流水账不要写在这里 —— 那是提交历史的事；**任务与进度也不要写在这里** —— 那在 `.ai/prompts/`。

## 硬事实（实测结论）
## 已定口径
## 方法论
```

⚠️ **已存在就不要覆盖** —— 只补缺的章节，内容往对应节里追加。

### `.ai/rules/README.md`（**只有真要建 `.ai/rules/` 时才写**）

```markdown
# .ai/rules/ —— 规则专题

**规则正文在仓库根 `AGENTS.md`**（AI 的常驻入口只认那个位置）。这里只放将来拆出去的长篇专题。

约定：一篇一个主题，文件名说明主题；放进来的同时**在 `AGENTS.md` 里留一行指针**。
```

## 4. `AGENTS.md` 里要加的那一节（**原样复制**）

这一节就是"AI 执行任务时的指引"。建完之后 AI 只看它，**不再需要读本文**。

````markdown
## `.ai/`（AI 产出物：放哪、何时放、怎么写）

`.ai/` 下**全部进库**（`.gitignore` 里没有 `.ai/` 相关规则）—— 放进去就会被提交、被下一个人读到。
所以只放**契约与知识沉淀**（换台电脑、换个人都要知道的东西），临时产物别往里放。

| 路径 | 放什么 |
|---|---|
| `.ai/memory.md` | 长期记忆 —— **实测硬事实 / 已定口径 / 方法论**（不放任务与进度） |
| `.ai/rules/`（**按需创建**） | 规则专题。**规则正文就是本文件**；只有长到必须分篇才建这个目录 |
| `.ai/prompts/` | 任务书 / 分阶段计划 / 待办清单 —— **进度只在这里** |
| `.ai/tools/` | 工具与探针的**源码**（可运行的东西） |
| `.ai/evidence/` | 被注释或结论**引用**的证据件（渲染页 / 截图） |

### 何时存、存成什么样

| 触发 | 存哪 | 怎么写 |
|---|---|---|
| **实测出一条新结论**（端点行为 / 框架行为 / 本机限制） | `memory.md` §硬事实 | 一条一个事实，注明"实测"与日期；**当场追加**，别攒到收尾 |
| **用户定了新口径**（推翻或补充既有决定） | `memory.md` §已定口径 | 一行写清代际关系（新口径 + 谁裁的 + 旧口径作废），并在答复里点明"这是新口径" |
| **踩到坑 / 需要禁令**（"这样做会崩"） | `memory.md` §方法论 | 写"症状 → 根因 → 正确做法"，别只写结论 |
| 接手**一件分阶段的活** | `prompts/` | 一阶段一节；做掉一期就回填状态，别另开文件 |
| 写了**可运行的探针 / 脚本** | `tools/` | 文件名说明它验什么；在引用它的代码注释里写相对路径 |
| 生成了**会被引用**的图 / 渲染页 | `evidence/` | 前提是**已经**被注释或 `memory.md` 引用；没人引用的截图不要放 |

### 怎么存（硬规矩）

1. **记忆只有一份**：追加进 `.ai/memory.md` 的对应节，不开 `memory-2.md`，同一件事不写两处。
2. **判据是"换台电脑、换个人需不需要知道"，不是"今天干了什么"** —— 流水账属于提交历史。
3. **一次一条，带日期与出处**（`2026-10-17` / `走查 #85` / `决策 #49`）；出处文件已不在仓库**也要写**，它是历史锚点。
4. **作废要留痕**：推翻旧条目时写成 `~~旧口径~~ → 新口径（谁裁的 · 日期）`，并**点名废止了谁**。
5. **`.ai/` 下不许放密钥**（`.env` / API Key / token）：这里全进库，放进去就等于提上去。凭据按项目既有的铁律走。
6. **改 / 移 / 删 `.ai/` 下被引用的东西前，先 `grep -rn` 全仓引用**（注释里写的是相对路径，含"见某某文件"这类间接引用），改完同步更新注释。
7. **`.ai/` 的改动单独提交**，信息写"记了什么结论" —— 别和代码改动混在一次里，这样 `git log -- .ai/` 就是一部结论编年史。
8. **任务与进度不进 `memory.md`** —— 当前任务、未完成、待目视一律写进 `.ai/prompts/` 的对应文件（**做掉一条删一条**，别攒"已完成"）；`memory.md` 只留事实、口径与方法论。
````

要加进 `AGENTS.md`，**编号按它原来的排法**（本文里写成 `##` 一级小节，是为了不被外层围栏截断）。

仓库根**没有** `AGENTS.md` 就先建一个最小入口（标题 + 一句"本仓库的 AI 规则都写在这里"），再加这一节。

---

## 5. AI 的执行步骤（照做）

```bash
mkdir -p .ai/prompts .ai/tools .ai/evidence
```

1. 建目录（上面那条命令）。`.ai/rules/` **不要预建** —— 真有一篇长专题时再建，建时一并写 §3 那个 README。
2. 把本文复制到 `.ai/init.md` —— 留住这份脚手架（下次开新项目还要用它）。
3. 写 §3 的 `memory.md` 模板；`memory.md` 已存在则**只补章节、不覆盖**。
4. 把 §4 那一整节**原样**写进 `AGENTS.md`（两张表 + 八条硬规矩都要），编号按它的排法；
   没有 `AGENTS.md` 先建最小入口。**这一步做完，AI 的指引就落在项目里了**。
5. **别给 `.ai/` 加任何 ignore 规则** —— 它全进库；顺手 `git status --short` 看一眼文件是否都可见。
6. 回报：建了什么、`git status` 的结果、以及**任何没按本文做的地方**（有就说明原因，不要偷偷改）。

---

## 6. 已知坑

- **别把入口文档搬进 `.ai/`**：harness 只去仓库根找 `AGENTS.md`，搬进去等于没人读。
- **别在 `.ai/` 下放密钥**：`.ai/` 全进库，放进去就等于提上去。凭据放仓库外，或用已被忽略的文件。
- **`memory.md` 会越长越像流水账**：判据是"换台电脑、换个人需不需要知道"，不是"今天干了什么"。
