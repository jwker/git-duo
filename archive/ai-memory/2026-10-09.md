## 用户提出：上传图片能不能在调 API 之前先压缩到 1MB 以内

**背景**：8.4 刚落地，`AddFileSheet` 的两个上传出口都是「超 1MB 就在选中那一刻拦下，提示引导网页端」
（`CommitSheetCopy.tooLargeHint`；判据 `SaveFile.maxContentBytes == FilePreviewKind.maxInlineTextBytes`）。
`AddFileSheet.finish(...)` / `EditorViewModel` 两处各判一次。

⚠️ **它推翻一条已登记规格** —— `PRD §5.8` 与 `TECH_SPEC §9.6` 的「相册图片**取原始字节、不重编码**、
重编码会改内容与体积」（决策 #70③）。⇒ 属**规格变更**，要走文档先行 + 登记新决策（同 #47 的处置方式）。

### 探到的事实（本轮）

- **可行性**：`ImageIO` / `CoreGraphics` 是系统框架，**零第三方依赖**（决策 #12）不受影响；
  项目里**目前一处图像处理代码都没有**（`Packages/` 下无 `import UIKit` / `ImageIO` / `canImport`）。
- **四个包都声明了 `.macOS("15.0")`**（`GitDuoDesign` 的注释写明"仅为在宿主机跑 swift test"）
  ⇒ 承载压缩的包**要么用跨平台 API（ImageIO 两个平台都有），要么 `#if canImport(UIKit)`**。
- **落点倾向**：机械（编解码）放 `GitDuoCore`（本地基础设施，跨平台 ImageIO，`targetBytes` 作参数）
  + 策略/文案放 `GitDuoKit`（它依赖 Core；而 Core 不能依赖 Kit）。
  ⚠️ **不能放 App 层** —— `GitDuo` target 没有测试 target（决策 #34 的原话）。
- **并发**：`AddFileSheet.handlePhoto` 是 `View` 的 async 方法 ⇒ 默认 MainActor；
  压缩要显式挪到 nonisolated / actor 上，否则大图重编码会卡界面。

### 待用户拍板的三个点（已提问）

1. **覆盖范围**：只压相册那一支 / **两支都压（推荐）** / 全部图片统一重编码
2. **策略**：**自适应降质 + 兜底引导网页端（推荐）** / 一刀切固定档
3. **截图与 PNG**：**保持 PNG 只缩边长（推荐）** / 统一转 JPEG / PNG 不处理

⚠️ 必须诚实告知的三条边界（**不承诺"一定能压到 1MB 以内"**）：
① 极端图（超大像素 / 已重度压缩过的 JPEG）到下限仍可能压不下去 ⇒ 兜底仍是那条"引导网页端"提示；

**必须让用户看得见**（文案是契约；参照上传出口已有的那行只读「将写入 {路径}」的做法）。

### 先核实"要不要做"（外部事实，不是照字面做）

WebSearch 确认：GitHub 的 markdown 渲染器**只支持 PNG / JPG / GIF / WebP / SVG**；
**HEIC / TIFF / BMP / RAW 浏览器渲染不出来** —— 而 **iPhone 相机默认就是拍 HEIC**（重灾区）⇒ 需求成立。

⚠️ **顺手修正了用户的字面要求**：用户说"转成 PNG"，但 **HEIC 转 PNG 体积翻几倍**（PNG 是无损编码），
多数会被缩到 800px 甚至更小才塞得进 1MB，而画质并不会比转 JPEG 好。⇒ 用 AskUserQuestion 收三个设计点，用户全取「推荐」：
① **白名单放行**（只转 GitHub 渲染不出来的）② **按源选输出**（带 alpha / 源无损 → PNG，其余 → JPEG）③ **扩展名跟着改**。

   ① 叫「默认收藏夹」却不是默认（新收藏掉进一个没有「默认」标记的夹）② 不叫却被标成默认（那个标记指向一个**可删**的夹）。
   改成算出来的之后，磁盘上只剩 `name` 一个字段，脱钩无从谈起 —— 测试里用"JSON 文本里不许出现 `isDefault`"钉住。
2. **`ProfileStats` 三个字段全 Optional**（初版只给 `followers` 加了）。
   理由：GraphQL **允许部分成功**（`data` + `errors` 并存）⇒ "日历那一格没拿到、两个计数拿到了"是**真实可达**的形状；
   前两个做成非可选就表达不了它。⚠️ 这不是"防服务端不返回 followers"（官方两形状都列为必需，已核实），
   而是在**忠实表达"这一项这次有没有拿到"**。
3. **`LoadMyConversations.Result` 只存 `nextCursor`，`hasMore` 派生**（初版存的是 `hasMore: Bool`）。
   这是**编译错暴露出来的**：续页时想要游标却没有（`error: value of type 'Result' has no member 'nextCursor'`）。
   真实后果比"少写一个字段"重得多：两份状态一旦有一处没同步，就会出现"`hasMore` 说还有、游标是 `nil`"
   ⇒ 每次点「加载更多」发一条 `cursor=nil` 的请求（**回到第一页**）⇒ 屏幕原地打转 + 配额白扣。
   与 `PagedListState` 既有纪律同源：**`nextCursor` 是唯一真相**。

### 关键口径（都写进代码注释了）

1. ⚠️ **格子尺寸由可用宽度算出来**（`TECH_SPEC §9.14` 末段明令），**不许写死像素**。
   只声明比例（`aspectRatio`），由 `Canvas` 拿到真实 `size.width` 反算一格 —— 原型那个 `11px` **没有抄**。

2. ⚠️ **刻意不做横向滚动**。原型 `.hm-grid{overflow-x:auto}` 在 40 列时已溢出

   （`cellSize` 夹下限 + 外面套 `ScrollView(.horizontal)`）。
3. ⚠️ **档位越界是夹取，不是回落到无贡献** —— 夹到最深那档至少看得出"这天有贡献"；
   回落会让那些天变空白，而"图少了一块"与"本来就没有"在屏幕上分不出来。
4. ⚠️ **`nil`（补位）不画** —— 头尾两周不足 7 天，那几格该露出卡片白底。
5. ⚠️ **`MenuRow.systemImage` 必须是 Optional** —— **设置页那五行在原型里一个图标都没有**
   （`12-me.js` 里没有任何 `svg(...)`），而「我的」页与收藏夹页那几行都有。
6. ⚠️ **尖角与前导图标同色（`--text2`）**，不是 `.chev{color:var(--text3)}` 那个更浅的灰 ——

### ⚠️ 本轮两个教训（都不是业务问题）

1. **我自己写的测试会让整套 `make test` 永久挂住 —— 比"测试失败"贵得多。**
   `cacheSharesInFlightRequest` 用闸门替身 `waitForCallers(2)` 等"两个调用者都进来"，而这条用例要证的
   **恰恰是"两处只打 1 次源调用"** ⇒ `callCount` 永远到不了 2。而 **`swift-testing` 默认没有超时**：
   外部只看到"命令不跑完、一个字不打印"—— 我白等了 **11 分 45 秒**才起疑（一度以为是"编译慢"）。
   **判据：写下 `waitForCallers(n)` 之前先回答"这段代码最多会打到源几次"，n 不能超过它。**
   （已写进替身注释 + `DETAILS.md §12`。）
2. **工作区里那份 `REVIEW-CHECKLIST.md` 不是 HEAD 的那份。** 提交前对 diff 起疑（"我只改了 5 处，
   怎么 1795 行"），查下去发现它是一份**被 Markdown 格式化器重写过的旧快照**：
   缺 HEAD 已有的整段内容（如「P2 已过 ≠ 令牌带 `Starring`」）、**10 处 HTML 实体转义**（`&#x7528;户`）、
   **534 行行尾补了两个空格**、表格被对齐重排、`清单 C` 计数还从 2 掉成 1。
   ⇒ 处置：**`git checkout HEAD -- REVIEW-CHECKLIST.md` 恢复正本，再在它上面重落本片编辑**（不试图"修"那份）。
   ⚠️ 顺带说明：**上一节记的"清单 C 三处全部改成定案口径"实际没留在文件里** —— 那份快照把它盖掉了，
